## Implementation approach

1. Restore the supplied source and replace `mysql2`, Manus OAuth, Manus runtime APIs, and `/manus-storage/...` URLs with the official Supabase JS/SSR clients. Use only the Supabase project URL and publishable key in the app; never require a service-role key in the runtime. Add SQL migrations for project/gallery tables, owner RLS, and a private screenshot bucket whose read policy permits only published gallery images or the verified owner.
2. Preserve the owner-only studio. Authenticate using Supabase Auth with Next.js server-side cookies, and authorize the owner by checking the user's UUID against a private `portfolio_owners` registry table via a database function. Only a Supabase project administrator can seed that registry. Verify the owner on every private server operation and enforce matching database/storage RLS policies. Keep public reads limited to published projects; never create a development auth bypass or seed fictional projects.
3. Serve screenshots through a same-origin `/media/[imageId]` route that checks the published DB record before streaming the private object. Permit draft-image preview only for the verified owner and mark it `private, no-store`; cache published media for a short period and version its URL on image replacement. Preserve cleanup warnings without exposing orphaned objects.
4. Rebuild the public page hierarchy around actual case studies and buyer confidence: an art-directed hero, visible project archive, client-relevant services and process, truthful proof, and direct inquiry paths. ## Project structure

- `app/`: App Router layout, portfolio home, case studies, admin, API routes, `/media/[imageId]` image proxy, favicon, sitemap and robots metadata.
- `components/public/`: data-driven project rail, technology list and public-only widget script loader.
- `components/admin/`: owner project and screenshot management interface.
- `lib/supabase/`: browser, request-scoped SSR, public read-only clients and cookie policy.
- `lib/`: owner checks, Supabase data access, site URL, image URL/versioning and upload validation helpers.
- `supabase/migrations/`: schema, RLS, and private-bucket policies.
- `public/`: site assets plus preview-only route metadata not included in the Vercel archive.
